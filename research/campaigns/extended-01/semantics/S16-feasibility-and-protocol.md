# S16 public identifier normalization: feasible, explicitly supplied invariance

**A narrow public-only canonicalizer is mechanically sound for all1,024 frozen S12 original/renamed pairs.** It does not establish graph correctness or learned lexical robustness. No model was instantiated or run, no checkpoint/threshold changed, and no new prediction outcome was inspected. The S12 renamed collapse is the disclosed motivation for this follow-up engineering diagnostic, not a fresh hypothesis selected without prior evidence.

## Actual input and copy contract

S12's actor receives token lexical SHA256 bits64 plus position/length, sin(position), cos(position) and0. It has no explicit variable-case feature or typed identity inventory. Copy candidates include **all public tokens**. `semantic_scaling.decode` maps a predicted token index to the first occurrence of its exact token string. The programmer must therefore supply identifier-span recognition before any safe lexical substitution; the existing public copy inventory alone does not say which words are identities.

The additive functions in `campaign_semantics_identity_contract.py` accept only text-only `ActorInput`. A strict English renderer parser recognizes `You know these facts: … . The pattern is … . What is the unify … ?`, semicolon-separated parent predicates, binary infix `x parent y`, and3–5-argument `parent: x, … and y`. It marks only argument identifier occurrences, preserves every other lexical token, punctuation, whitespace and token position, and never constructs a graph, selects a matching fact, computes a query answer, reads node labels or uses hidden metadata. Visible uppercase/lowercase supplies separate variable/name namespaces. This is an explicit parser/case convention prior, not learned language understanding.

Within each namespace, first public occurrence maps to the next fixed known lexeme: variablesA/B/C/D/E; namesalice/bob/carol/dave/erin/frank. Mapping is simultaneous, injective and per-example. First occurrence is taken from the actual displayed stream, not compiler node order, alphabetical source identities or semantic roles. A first `frank` can map to`alice` while a later original`alice` maps to`carol`, without cascading replacements. Known canonical tokens were verified in public TRAIN text, so training-vocabulary reuse is explicitly supplied.

The parser rejects unsupported syntax, mixed-case/unsupported identifier spellings, structural-token aliases, arity mismatches, more than four facts, and inventory overflow (five distinct variables/six distinct names). It does not guess or fall back. Mechanical arity2–5 support is distinct from the actual S12 population: all1,024 examples have arity4, with487 three-fact and537 four-fact examples. The result says nothing about free natural language, translated/multi-token aliases, shadowing, case-changing renames, more identities or broader grammars.

## Invariance and restoration

For a bijective case-preserving rename that leaves nonidentity text and equality relations fixed, corresponding identifiers have identical first-occurrence ranks within their namespace. Thus the normalized token sequences and all positional features are identical. Collisions between identities and nonidentity tokens are rejected, so every token's first-occurrence index is unchanged. A predicted copy index can consequently be read against the **original public token inventory** to restore its original spelling; no gold identity mapping is needed. Nonidentity copy mistakes remain nonidentity strings, absent pointers remain absent, and invalid indices fail. No predicted edge/kind/value/presence/slot or copy choice is corrected.

The full public audit read only each cache row's`text` field. The original/renamed cache hashes are pinned to the prior independent pairing audit. All1,024 pairs are accepted, with0 rejections and0 lexical hash collisions. Every pair has bit-identical complete FP32 and BF16 input features, equal lengths/masks, preserved identity positions and all-token first-copy indices, and exact original-inventory restoration. Per-row feature/public hashes and coverage appear in `S16-public-audit.json`; elapsed CPU time0.990096s, CUDA hidden. Existing identity-rule plus new adversarial mechanical tests pass14/14 in0.61s, including arities2–5, repeated identities, case distinction, canonical-name collisions, reserved-word resemblance, structural alias rejection, equality/role changes and invalid copy outputs.

This equality is an engineering guarantee on the observation, not evidence the model learned rename invariance. With an unchanged deterministic evaluation path, normalized-original and normalized-renamed predictions must agree because the model sees the same input; duplicating all renamed forward exports would add no scientific test. Merely making two inputs equal can preserve the same wrong graph.

## Prospective diagnostic, not yet implemented or released

`S16-prospective-diagnostic.json` binds all six unchanged S12 endpoints: constant/decay ×701/702/703, with the existing checkpoint hashes and original TRAIN-calibrated thresholds. No successful-seed selection, normalization search, threshold refit, retraining, checkpoint adaptation or hidden graph-based parsing is allowed. The single mapping above is fixed before any normalized forward. Normalizing original names can itself change learned lexical correlations, so the informative comparison is **frozen original versus normalized-original**, not just failed renamed versus normalized-renamed.

If independently reviewed, profiled and released by root, evaluate normalized-original once for all1,024 examples under each of the six frozen models. Preserve the existing original raw/calibrated prediction references by hash and score paired complete-graph repairs/regressions, identity-copy, node/edge/ordered-slot metrics and every attempted example. Retain all six seeds/arms even if normalization worsens them. Existing targets are scoring only and stay outside the canonicalizer/forward. Restore copies through original public token indices; use no target-derived identity list. Report normalized-renamed equivalence by the already audited **full input** equality, with no redundant large prediction export or claim of independently measured learned robustness. Programmed S10 equality/schema postprocessing, if reported, remains a separately labeled unchanged reference.

No accuracy pass is presumed and no competence gate is relaxed. A gain would support usefulness of this supplied normalization prior for the frozen finite English renderer; a loss would expose a lexical/distribution dependence even after vocabulary normalization. Either leaves historical S12 competence and raw unseen-spelling failures intact. Main cap is deliberately unset: a future source/profile/budget freeze and explicit root GPU release are required. This delivery contains only normalization mechanics, tests, public CPU audit and prospective design—no inference runner or training allocation.
