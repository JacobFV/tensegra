# Conditional learned-edge acquisition proposal after S17

Planning only; no implementation, allocation or training. If S17 leaves the trained3×3 edge failure materially unresolved, recommend **one three-arm matched continuation testing S09's predicted-pointer-conditioned contextual read**, not a new head family. This is a new prospective development study; S09's old from-scratch configuration is not the appropriate executable recipe.

S15 localization supports this specific question: on mixed3×3, presence/scalar values are exact512/512, ordered slots507, kinds478 and copying477, yet typed edges are exact1;455 cases fail only on edges. Gold-edge replacement gives456 complete graphs, but this is privileged localization, not a deployable solution. Held-out3×4 also has kind/copy/slot failures, so edge improvement on the trained motif must not be called compositional transfer.

The current actor already has multiplicative directed source–target interaction: relation-specific128-dimensional source projection dotted with a shared target projection. It is not an additive-only or independent-node edge classifier. Slot logits are additive source+target, but their507/512 component exactness does not identify them as the primary trained-cell bottleneck. Node states are decoded from eight workspace rows, while the successful copy probabilities do not feed contextual evidence back into those states. S09 tests that information path, retaining the bilinear edge scorer. A source/target-head replacement at the same time would destroy attribution. Failure of S09 would not by itself prove the edge scorer sufficient; it would reject this particular added contextual-read intervention at the specified exposure.

Use three arms with identical public information, targets, original first-identity copy objective and parameter set:

1. **Strong matched baseline:** historical actor, context_read off, two recurrent microsteps. It gets the entire identical English text and positional/hash features and is continued on the same S15 mixed4096 construction cache. The historical S15 old-shape-only control is not the equal-data baseline for this architecture question.
2. **Contextual read:** retain the eight-row workspace/canonical queries; shared existing blocks contextualize public tokens; the unchanged learned copy softmax reads those states through reused value/output projections, with the preregistered0.5 residual. Keep heads, objectives and all output requirements unchanged. No gold spans, role schema, graph edges, parser, normalization, exact equality, or token-aligned output candidates enter forward.
3. **Extra-workspace compute control:** original actor with extra shared recurrent passes, no contextual-read stream. Prospectively choose recurrence from the existing dense-MAC formula using the fixed cache's actual padded length/batching schedule. Freeze the integer rule and its mismatch before outcomes; do not blindly reuse9/10 passes from S09's54/64-token corpus. Report estimated arithmetic, observed whole-process/optimizer time and memory separately. Require this control in the initial comparison, not only after a favorable endpoint.

All arms restart from the same independently selected S11 seed201 parent/checkpoint3799ade595500a083b9a558b6a5bc97c5cbc1b8bdce6e7e4b86d97b937ea373e and inherited AdamW state, rather than branching from different S15 endpoints. Match S15 mixed cache/order, LR1e-5, width1024, capacity128, batch8,4096updates/32768 presentations, fixed arm-independent per-presentation negative-sampling RNG and evaluation schedule. Require exact parameter-name/state/optimizer mapping and off-path forward/gradient replay before training. Here data shapes are identical across arms, so realized sample pairs can also be identical. Log construction/token/node/edge exposures, not just updates. Intervention at continuation start is intentional; checkpoint0 evaluations expose its immediate perturbation and must not be selected away.

For calibration, prospectively use one matched-mixture TRAIN128 population and the inherited threshold algorithm for every arm, with the same indices as mixed S17 and one policy applied to all four DEV cells. Refit thresholds per checkpoint under that fixed rule only. Retain raw and historical-TRAIN-policy results as secondary references. This proposed decoder policy must be frozen before new predictions, not chosen per arm/cell from S17 or future outcomes. It tests learning under a common policy after the calibration diagnostic; it cannot overwrite S15 results.

Use all four existing S15 DEV512 cells, a fixed actual-TRAIN acquisition panel, and updates0/1024/2048/4096; endpoint4096 alone decides development. Report complete graphs, component conjunctions, typed/ordered micro-counts, reference/argument FP/FN, and paired repairs/regressions against both controls. A useful prospective promotion rule is trained3×3 calibrated exact≥52/512 and at least26/512 above **both** controls, with known-arity pooled retention≥103/1024 and no loss>51/1024 against either. Report held-out3×4 separately; requiring its own≥52/512 and≥26/512 advantage over both controls is necessary before any recombination claim. These remain single-parent development search criteria; the reused DEV is inspected. Reserve untouched confirmation and paired additional seed lineages for a separate frozen release. No automatic exposure extension or endpoint selection.

Method basis is already recorded in campaign `methods.md` and S09's primary-method notes: Dozat–Manning's contextual source/target scoring motivates accessible contextual evidence, and Universal Transformers motivates shared recurrent refinement. The existing actor is already a role-projected bilinear baseline; this proposal does not claim a new biaffine method. Word-aligned parser nodes would supply a stronger correspondence than our canonical queries and are deliberately not substituted. Priors remain ordinary tokenization/order/hash features, canonical output node ordering, fixed ontology/capacity, dense supervised graph/copy labels, and trained mixed-shape support. Learned pointer-conditioned soft retrieval is not symbolic identity restoration.

Cost is a real reservation, not parameter equality: S09 retains57,853,781 parameters but its old backbone/read MAC estimate is about4–5× baseline. Its old20-update profile measured2.0033 optimizer seconds and11.3356 full seconds; extrapolating only its optimizer rate to4096updates gives~410seconds before evaluation, but the S15 lengths/cache/continuation need fresh profiling. S15 mixed historical full occupancy was484.1414seconds, optimizer248.5729. Neither is a cap for the new three-arm job. Profile all three serially at20updates with identical evaluation counts before making a whole-process budget; the many-pass control may be launch-overhead dominated. If campaign budget cannot cover all three plus evaluation/archival, defer this study rather than omit the strong compute control or lower width silently.
