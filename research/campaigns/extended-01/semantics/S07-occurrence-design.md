# S07: occurrence-specific supervision with the original actor

Hypothesis: canonical identity copying is acquired more easily when each identifier occurrence is first aligned to its own observable position. The current first-occurrence target is a valid identity contract, not an erroneous label. This experiment changes only that privileged training target and tests whether the distinction helps ordered graph acquisition.

The existing English unification renderer exposes identity mentions in canonical occurrence traversal order across all 8,704 audited TRAIN/DEV constructions. Ident-node loss targets become their corresponding token positions. Entity nodes retain first-identity targets; all other heads, objectives, sampled pairs, curriculum, architecture, initialization and optimizer remain the S01 reference. No S06 token-state change. Deployment retains historical normalization to first occurrence and complete canonical graph metrics. Gold occurrence positions are never actor inputs, deployment masks, or calibration data.

Use width 1024, 8 workspace rows, four blocks reused twice, seed 201, batch 8, 8,192 unique TRAIN graphs and 65,536 optimizer presentations. Same 512 development constructions and first 128 TRAIN calibration rows as S01-N8192. Checkpoints at updates 0/1,024/4,096/8,192; fixed endpoint without early selection. New profile is 20 updates with 16+16 mechanical evaluation rows; provisional main refuses execution before measured budget freeze. Intended cap 900 full-process seconds, queue release required. No confirmation predictions or automatic extensions.

Prospective promotion requires calibrated complete DEV graph accuracy at least 10% (at least 52/512), at least five percentage points above S01-N8192, ordered-edge F1 > .90, and canonical copy accuracy >= .95. Report raw metrics in parallel. Failure remains informative and does not trigger an automatic confirmation run. Reusing development data makes this search, not an independent generalization confirmation.
