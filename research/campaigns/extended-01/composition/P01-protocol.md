## Exact observation contract

Use the unchanged `retention_data.make_batch(seed,count,32,distractors,8)` as a private generator reference. It samples uniform five operations; numeric integer/float types, Boolean compare; half-unit values with ties-to-even rounding for integer; and the original witnesses and independent query. This sampling includes the R04 rare float-zero failure; no balancing or resampling repairs it. Generate the public lowering problem by replacing the precomputed event with a table of typed numeric operand literals and four complete role-bearing instruction records, one per provenance/destination handle. All four records are shuffled, all eleven candidate handles shuffled, and all display names fresh. Six argument handles, one explicit absent handle and four provenance/destination handles retain their original Gaussian32 identities. The requested destination identifies the selected record. Complete evidence arrives in one fixed supplied observation; one lowering decision follows. No learned halting claim.

Public literal types have Python scalar semantics: integer operands execute integer arithmetic; float operands execute float arithmetic even when numerically integral; Boolean results arise only from compare. Arithmetic float witnesses are explicitly float; integer witnesses explicitly integer. Compare witnesses are integer `1-value` and float `0.5`; compare means ordered `<`, not `>`. The downstream query separately means `(result > threshold) XOR polarity`. For unary negation the absent operand is a zero key, absent table value, false second mask and zero second witness. A correct execution derives result type from actual scalar execution; no hidden output type reaches execution.

Training labels and reference events are stored separately from public rows. `model_inputs` accepts only public rows and includes the public numeric table and query (the reused ProposalModel ignores those extra features). Runtime `execute_proposal` accepts only public rows plus actual predicted op/pointers and a public acceptance decision. It has no label, gold result or reference-event argument. The table witnesses can statistically reveal answers—particularly multiplication's `(value,1)`—because this is the registered return distribution; the neural baseline must receive this same evidence. That is disclosed task structure, not a secretly injected answer channel. All wrong proposals execute their actual supplied operands. There is no gold binding restoration, clipping or reset.

Existing `ProtectedSession` provides five exact primitives. Public literals may reach16 because add/sub witnesses can exceed the result bound8. Result range[-8,8] and half-unit-grid checks enforce the declared R04 interface after execution. Nonfinite/runtime, role, pointer, unary-schema and range failures are explicit refusals. Destinations are append-only identities. Return provenance in this narrow adapter is the actual destination's public provenance key, not the runtime's rich ancestry string. Correct reconstructed events must match every original event tensor exactly, including type, operation, ordered identities, witnesses and masks. Other public context tensors are retained unchanged. This mapping of destination to provenance is supplied engineering.

## Acquisition recipe to freeze before release

Cross-entropy primitive plus destination/ordered-required-operand losses; unary second operand is masked in the historical loss. The historical bias-free query/key head maps the zero absent key to a zero query, so its absent-role logits tie: teaching an arbitrary null position would impose an impossible contract. The adapter therefore canonicalizes the absent operand from the PREDICTED primitive arity and the public null handle. This is a programmed schema guarantee, not learned null selection. Full semantic proposal accuracy includes primitive, destination and all operands required by the true operation, comparing the canonical actual prediction; report required-operand metrics separately. A wrongly predicted negation still executes its actual single operand, and a wrongly predicted binary operation must supply two actual numeric operands. No gold arity reaches forward or runtime.
