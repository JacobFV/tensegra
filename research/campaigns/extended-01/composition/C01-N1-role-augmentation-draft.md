# Draft: matched N1 operand-role augmentation study

Design outline only, requested after the retained C01 development analysis. Not frozen, implemented or queued. This is a new bounded intervention, not a repair of prior N1 validation. Existing C01 results remain unchanged. Root owns experiment IDs, population reservations and later release.

Hypothesis: N1's reversed-role failure reflects incomplete numerical generalization over witness positions despite correct addresses. A small public-record augmentation can teach the missing symmetry/direction cases without adding primitives, pretrained models or an exact operator to neural forward.

Compare two fresh N1 training arms with identical architecture, initial P01303 lowerer, head initialization, base public examples, optimizer, example-index stream and total presentations. One sees the unchanged generator. The other independently flips a fair coin per sampled example: heads uses its unchanged public row; tails swaps the two operand roles of every BINARY instruction in that row, including nuisance records. Unary records retain their explicit absent slot. No selected/gold instruction index is used to choose which record to transform. The requested destination, typed literal table, names and threshold/polarity are unchanged.

Precompute private targets by exact evaluation of the ACTUAL public requested record in each view. Add/mul scalar/answer targets are unchanged; sub/compare targets generally change. Ordered pointer targets always follow the supplied role order. The augmented model never receives the computed scalar, answer or gold pointers in forward: those remain the same supervised loss fields as before. Verify every augmented witness, type and range; assert all intended views stay in the bounded task. The view mixture changes the joint operand-witness distribution and increases distinct public views; it must NOT be called the unchanged R04 retention distribution. This intervention trains only the neural comparator, not the frozen hybrid/accessor.

Minimal proposed exposure: one LR.0003 (selected from the earlier calibration search),4000updates×256=1024000presentations per arm; AdamW.01 weight decay and existing summed answer/value/proposal losses. Same width1024, same sampled base-event indices. Proposed fresh16384/2048/4096 train/calibration/validation populations, with new initialization and data namespaces allocated before launch. Log per-base-event and per-view visits; augmented presentation count stays identical even though up to twice as many distinct views are available. No new test observations enter fitting. Both arms begin fresh from the same P01 checkpoint, rather than continuing the already evaluated N1 state.

Use the same predeclared selection rule for BOTH arms on fresh paired clean and reversed calibration views: maximize minimum answer-correct count over the two views; ties maximize summed count, then earlier checkpoint. Proposed checkpoints0/250/500/1000/2000/3000/4000. This tests augmentation under a common robustness objective; it does not privilege the augmented arm with extra calibration information. Report clean-only counts too, and preserve every checkpoint outcome. Validation is untouched until selection.

Primary outputs are clean and reversed answer accuracy, and paired augmented-minus-unaugmented differences on the same4096 base examples with paired uncertainty. Proposed competence target>=4015/4096 in BOTH views for the augmented arm; explicitly report any clean cost rather than hiding a robustness/clean tradeoff. Ordered proposal and auxiliary scalar accuracy, conditional on correct lowering, remain diagnostics. Report each primitive, unchanged-answer cases, changed-answer supports, and soft numeric retrieval residuals. Multiplication commutativity and comparison direction are separate table rows. Nuisance/order/name controls may be retained at the same examples with name renaming labeled a no-op. No scalar-uniformity or unrestricted arithmetic claim follows from binary answer success.

There is no new hybrid run in this minimal comparison. If a later C01 confirmation adopts an augmented comparator, it must freeze that recipe on new paired populations and compare answer-only against answer-only, retaining the existing hybrid joint semantic gate and inherited-compute disclosure. Store final per-LR/arm model AND optimizer/RNG/sample-generator state in this new study if continuation is to remain possible; the original C01 runner did not preserve optimizer endpoints, which remains disclosed.

Root must settle/freeze the proposed selection rule, seeds, checkpoints, metrics and CPU tests before a profile/release. Estimated cost should use N1's measured75.14s for two LR runs only as a starting point; added paired calibration/view preparation must be profiled or conservatively bounded. No outcome here is predetermined and no GPU work is authorized by this draft.
