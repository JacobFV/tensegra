# C01 conditional design v1 (not implemented or released)

A scheduled bounded pipeline: complete public instruction/table/query → learned P01 primitive/destination/ordered pointers → existing exact primitive → constructed return event → frozen R04 scalar accessor → frozen R05 learned threshold/polarity consumer. This is one learned lowering followed by exact arithmetic and a learned query decision. It is not two independently learned symbolic lowerings, autonomous orchestration, crystallization, general numerical reasoning or language grounding.

Entry requires independently audited P01 full ordered proposal >=98% on each of three fresh validation populations, exact event fidelity, R04's existing restricted-mixture pass, and R05 >=98% at every consumed fresh validation cell across three backbone populations. R05 development is insufficient. Composition outcomes cannot retroactively promote a failed interface. Coordinator/reviewer must confirm concrete frozen checkpoint hashes and the scope of each interface. There is no C01 implementation until these gates pass.

R04 contract remains the original generator mixture at delays0/1/2/4/8/16 and distractors2/8. Errors in lowering may create a different event mixture. Report that shift explicitly, stratify correct/incorrect proposals and refused/out-of-range events, retain all examples, and never infer a reliability guarantee for wrong-lowering events from R04. Test32 is reserved extrapolation only. The separate balanced float-zero diagnostic remains prominent and cannot become primary by resampling.

R05 interface planned by returns worker: `workspace(model, public, delays, drop=False)` yields B×1024 features. R04 frozen `head((features-mean)/scale)` yields33 scores. `consumer_input` softmaxes those scores and concatenates threshold/8 and polarity, then a frozen35→1024→2 GELU consumer emits the answer. Each backbone10/11/12 uses its own matched R04/R05 checkpoint. No exact scalar bypass enters the learned consumer. Confirm actual saved artifacts before writing a runner.

## Fair controls and measurements

Primary learned hybrid; oracle lowering through the identical executed return/accessor/decision path; oracle return with original generator event; and exact-copy engineering scalar interface with an appropriately trained matched consumer (a privileged interface control, not a learned discovery). Separate arithmetic-exact-plus-exact-query is an engineering ceiling. Drop/wrong/swap interventions affect return ingestion and persistent reads exactly as R05; wrong/swap results and witness inventories are actual supplied facts, never gold resets. Unrelated-input controls change nuisance records/context while preserving the requested record. All schedules, delays and distractors are paired.

The strongest neural-only comparator gets the SAME complete observable instruction records, operation codes, requested destination, typed numeric table, threshold/polarity, nonce keys and context. It cannot be restricted to query-only or hide witness values. Proposed fair baseline uses the same learned keyed record/operand retrieval with a1024-hidden value/decision MLP fed retrieved typed numeric operands, op cue and query; an additional contextual1024-wide attention baseline can read all records and table to remove the soft-selection bottleneck. Train end-to-end on answer and the same allowed proposal supervision with matched example/update exposure; report parameters/FLOPs/optimization sweeps and validation-only selection. No external primitive or exact operand gather in the neural-only forward; an oracle-address neural arithmetic control localizes failures. If a stronger reasonable neural baseline succeeds, retain the tie. Final baseline recipe needs pre-outcome reviewer approval and a profile, not a knowingly underpowered baseline.

For every pair retain original target answer, actually supplied valid-return answer, predicted answer, proposal correctness, refusal status, event type/value/operator and intervention masks. Wrong/swap and wrong-lowering analyses report both original-answer and supplied-answer agreement, all examples and changed-answer subsets with support. Dropped/refused returns have no supplied answer: never fabricate one, and include them as failures for primary task success. Report paired effects and uncertainty; do not multiply marginal interface accuracies to assert end-to-end success. The clean gate would require >=98% each prospective4096-example validation cell across all three matched backbones; freeze all populations and confirmation recipe before any C01 run.
