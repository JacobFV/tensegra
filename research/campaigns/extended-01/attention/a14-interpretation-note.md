# A14 comparison scope and possible next question

A14's primary comparison changes inference reads within each identical frozen all-record model. All policies share6000-update training, parameters, data and residual/readout; this isolates the consequences of supplied per-head versus common reads. It does not compare graph-induced Q/K bias against record attention, and confidence/route diagnostics are not a structural-attention superiority result. No per-head or mean-head route loss exists: training supervises payload classes at every node/reverse step for depth1–4.

Fresh seeds share96000 generated training presentations and the same1024 heldout graph events per shape. Initialization and training record-order RNG vary. Development monitoring is isolated from training RNG, so the recipe is not claimed to reproduce A11's exact segmented trajectory. A06 references share the new heldout public graph facts but have1000-update training histories, different supplied neighborhood interfaces and fixed prior concentration interventions. Report their performance as competitive engineering references; do not pool their training costs or infer a matched architecture advantage. Existing competitive keyed context/gather/message evidence remains visible.

Instrumented confirmation runtime includes observations, scoring and export. Profile bare forwards use a separate workload and report generation/tokenization preparation, warmup and repeats separately. Training+monitor peak allocation differs from inference peak after optimizer/gradient cleanup. Parameters allocated or receiving gradients do not equal effective capacity or FLOPs. These scopes support descriptive accounting, not a normalized speed/memory superiority claim.

**Conditional next-branch recommendation, not registration:** if A14 replicates the common-read effect, a supervised grounding branch adds attributable knowledge only by replacing an actually supplied binding with a predicted one. Merely relabeling random identity codes, training another attribute matcher or making record-order permutations harder would largely repeat existing explicit-coordinate matching.

The smallest informative new boundary would predict the source/destination-to-node binding or observation-to-edge facts currently inserted by the public record tokenizer, from a declared observation representation that does not already expose that binding as an identity coordinate. Use explicit grounding supervision and hold the execution interface fixed; compare predicted bindings with the same model under oracle bindings, and with competitive contextual/neighbor retrieval given the same observations. Separate grounding accuracy, graph-fact errors and conditional execution given correct grounding on heldout identities/compositions. Control observation informativeness so failure is not unidentifiable data, and keep oracle labels out of inference except in the named diagnostic reference.

This would test a new supervised perception-to-graph interface, not emergent semantics or latent planning. Any attention-specific benefit would still require equal-observation competitive baselines and matched training/search cost. If A14 does not replicate, inspect its seed/route/transport failures before adding grounding complexity. No grounding implementation, new loss, dataset or GPU run is authorized by this note; A14 outcomes decide whether to propose a separate protocol.
