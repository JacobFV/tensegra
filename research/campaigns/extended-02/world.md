# Workshop v1: public control interface

This is a bounded structured-observation environment, not language understanding or a supplied primitive schedule. `generate_world(seed, categories=2, choices=3, locations=5, obstacle=False, **overrides)` constructs a hidden `WorldSpec`. `Workshop(spec, executor=protocol_executor)` exposes only `observe()` and `step(Action(kind, arguments))` to policies. `evaluate()` is evaluator-only. Candidate policies must receive serialized public observations rather than Python environment references.

The public goal requires exactly one item per category, within weight/cost limits and public pair incompatibilities, then delivery and verification. Inventory category/handle pairs are visible. Per-item weight/price and the route map require inspection. The generator plants some feasible selection but shuffles item order and opaque handles. This guarantees feasibility, not hardness or optimality; computational leverage must be measured.

Actions: inspect, start_subset, add_constraint, build_route, call, retrieve, choose_item, commit_pending, use_return, direct commit_subset/deliver, verify, think, abstain. All outcomes come from simulator checks. No optimal-action mask exists. `action_catalog(observation)` enumerates syntactic choices including premature verification, duplicate inspections, wrong return-type use and calls with incomplete constraints. It never computes feasible subsets or shortest paths. Direct user-supplied routes/selections remain permitted. Public candidate counts grow with accumulated drafts/returns; episode cap bounds growth.

`start_subset(handle)` compiles currently inspected items into an ordered domain and includes **no constraints**. `add_constraint(problem, constraint)` chooses capacity, funds or incompatibility from the public goal. The deterministic lowering compiler translates named public constraints; it does not solve, inspect hidden fields, add omitted constraints, or repair omitted items. `build_route(handle,start,goal)` copies the inspected map using the agent's endpoints. Budgets are agent-selected. `protocol_executor` invokes versioned primitive APIs. Missing subset capacity/funds default to total item weight/price (explicitly unconstrained); omitted incompatibilities remain absent.

Solver correctness concerns the submitted instance; final item selection is independently validated against the actual world. A certified solution to an incomplete model may therefore fail environmental commit. A result status is not credited as task completion.

Returns have opaque deterministic address-RNG handles, explicit provenance and state versions. Payloads require `retrieve(handle)` and remain in public persistent retrieved memory thereafter. `use_return(handle, as=...)` performs exact addressing/copying after retrieval, not neural reconstruction. Multiple observation/computation returns coexist. Wrong types are rejected. Route results become stale after a discovered obstacle; subset results remain valid across route-only changes. Inspection alone does not invalidate records. Environmental success requires explicit verify after delivery.

`encode_observation` and `encode_action` are compact public summaries for baseline policies; they are not lossless or declared sufficient statistics. Full JSON is equally available. Raw handle spelling never enters numerical features. Equality, item category, known attributes, draft constraints, result status/provenance, retrieval availability and public staleness may enter.

Mechanical tests cover observational equivalence under hidden-state changes, feasible generation, argument/order validation, immutable persistent addressing, no implicit constraint completion, resource budgets, and obstacle/stale handling. Initial seven pure-Python mechanical functions passed in 0.0131 CPU seconds; package import was stubbed solely to avoid unavailable local torch, not to bypass world code. Full integrated pytest remains root verification.

Limitations: this first version supplies typed observations and deterministic problem compilation. It does not yet establish strategy acquisition, complexity-class hardness, reduction generalization, learned copying or metareasoning. No concurrency, language renderer or free-form host execution exists. Reference policies must operate on the same observation/catalog and account for their search work separately.

Pre-training contract repairs: movement is available per visible outgoing edge without tools; macro routes and individual moves both consume actual edge distance, including partial progress before obstruction. Public travel price and allowance are distinct from solver work. Direct routes can be absent or expensive. Return records retain immutable call/problem snapshots; later draft mutation cannot alter return provenance. Candidate features include public retrieved payload totals/path endpoints and current matching-draft return status, plus pending category/compatibility and aggregate resource use. These are public comparisons, not hidden feasibility labels. Exact structural reduction coverage is logged evaluator-only at call time. Validated timeout incumbents may be consumed as feasible results, never certified optimal results.

`address_seed` is an explicit independent RNG input (default 0 for mechanical reproducibility); experiments must vary it independently from semantic construction and use renamings for invariance tests. Current feature sizes are 26 observation and 67 candidate. The exact payload read path is supplied, including primitive-specific tuple interpretation. Policies learn which returned record to retrieve/use. `protocol_executor` uses OS-bounded process execution and independent payload validation; parent and child CPU charges are distinct. Ten mechanical tests now pass in 0.0202 CPU seconds. No policy experiment preceded these fixes.

Executor lifecycle comparison: `protocol_executor(..., execute_call=None)` defaults to isolated process-per-call execution. A harness-owned `BoundedSolver` context may instead pass `functools.partial(protocol_executor, execute_call=solver.execute)`. Problem lowering, budget requests and independent result validation remain identical. There is no module-global worker or daemon. `solver_cpu_seconds` combines measured parent call CPU and the executor's per-call child CPU diagnostic, including live persistent workers. The outer harness's inclusive process-tree receipt is authoritative for campaign accounting: never add this nested diagnostic a second time. Persistent worker startup/idle/shutdown costs belong to that outer receipt even when absent from per-call values.
