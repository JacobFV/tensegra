# Extended-02 progress — September 24, 2026

Snapshot: campaign source `9cbbd00e` and the subsequent encoder audit notes.
This is an interim progress note, not a final campaign report. The coordinator
owns the live queue and resource ledger; the campaign is continuing.

The strongest result so far is a learned closed-loop workshop policy on easy
instances. The main open problem is acquiring useful control when resource
conditions, observation requirements, and recovery demands change. A new audit
also identifies missing public information in the neural input representation.

## Completed and audited results

**E03: easy supervised acquisition.** Both width-1024 controllers solved all
128 shared development episodes at their frozen 600-update endpoints. Final
raw trajectories and costs were independently reconstructed. Each episode used
two correctly formalized solver calls, two retrievals, and two returned results.
Evaluation did not supply an action schedule, but training imitated an
always-tool teacher. This demonstrates acquired execution of that behavior,
not learned resource allocation or general planning. There is only one
initialization per architecture. The lightweight model has 2.21 million
parameters; the recurrent model has 26.36 million, so they are not parameter
matched. References see richer public JSON than the neural feature encoders.

**E04: frozen transfer.** Each cell contains 512 fresh development worlds,
shared across methods. The lightweight policy solved all easy, medium, hard,
expensive-tool, and expensive-travel episodes. It solved zero tight-budget
cases and 309 obstacle cases. Its expensive-tool utility was about 0.369,
versus 0.914 for the supplied cheap-first reference: success did not imply
efficient resource use. The recurrent policy solved all easy cases and zero
cases in the other six conditions. Independent trajectory analysis localized
failures to premature or missing computation transitions, incomplete
formalization, exhausted budgets, and stale route reuse after obstacles.
These are not observations of incorrect exact solver execution.

**E02: reference repair.** On 512 paired tight-budget worlds, the original
cheap-first reference solved 138. A versioned greedy-route fallback raised
that to 455; exposing an exact remaining-budget call option raised it to 501.
Combining both also solved 501. All four variants solved all standard-budget
worlds. The 11 remaining failures all exhausted subset-search allocations of
16 then 112 without a feasible incumbent. Restarted search repeats work, so
this does not prove an intrinsic 128-work lower bound. The audit checked raw
outcomes, public-condition comparability, costs, and successful selections.
These are supplied policy and API repairs, not learned metareasoning.

## Current acquisition and representation diagnosis

E05 broadens the supervised curriculum rather than assuming the easy policy
will transfer. Its lightweight endpoint currently solves 57 of 128 mixed
development episodes; the paired recurrent run is still running at this
snapshot. The frozen recipe remains unchanged while it completes.

The encoder audit found two exact counterexamples under source `a9337b71`.
Both have identical complete neural observation vectors and candidate matrices,
but their public-information teacher chooses different action kinds:

- An incompatibility between two not-yet-selected items changes whether the
  teacher chooses an item or builds a subset problem. That relation is missing
  from the encoded inputs before any item is pending.
- A downstream route weight changes whether the teacher moves or requests a
  route computation. Current outgoing-edge features and memory counts do not
  expose the changed downstream weight.

Perfect imitation of these paired labels is impossible from those identical
inputs. This does not measure how often the collision occurs, prove task
completion impossible, or attribute every E05 failure to the encoder. Separate
identical-feature inspection ties can also create a cross-entropy floor while
argmax selection still succeeds; they are a different issue.

The next repair is a versioned public relational memory shared by both model
families. It will expose observed facts, ordered references, constraints,
returned records, and dependencies without supplying solved routes or feasible
subsets. A lightweight context reader must remain a strong comparator. Any
benefit over the lossy encoder first establishes an input-contract repair;
attention-bias superiority requires a separate equal-information comparison.

## Population status and scientific limits

A real six-member population runner has been implemented, including selection,
checkpoint inheritance, mutations, independent multistart and single-learner
controls, and resumability. A 36-update population profile and mechanical tests
validate operation only. Main population training has not yet established an
evolutionary advantage. Descendants will not count as independent replications.

No current result establishes novel primitive composition, calibrated readiness,
robust recovery, or efficient general resource allocation. Exact algorithms,
protected payload storage, and the typed API are supplied. Action selection is
learned in E03–E05; teacher schedules are privileged training labels. Failures
and original recipes remain preserved while the campaign follows the localized
input and control problems.
