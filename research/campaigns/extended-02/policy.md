# Public candidate policies and population utilities

The model consumes only `obs[B,O]`, `candidates[B,A,C]`, and a boolean public API-validity mask. It returns action logits, a scalar critic, and optional recurrent state. Candidate order is equivariant; opaque handles should be encoded by the world adapter according to their public identity relationships rather than their numeric spelling. This module cannot inspect an environment or executor. Public observability must additionally be audited at the adapter boundary.

`PolicyConfig` defaults to **1024** dimensions for both families. The lightweight comparator uses one feedforward context transform and a nonlinear candidate scorer. The recurrent comparator uses four independently parameterized attention/MLP phases per step, with four workspace rows by default. Phases attend to current state and currently supplied public input, recomputing keys/values with no historical KV cache. Both use the same width and candidate scorer shape; parameters and actual compute differ and must be reported. Repeated calls advance microsteps; the runner chooses whether a latent-step action leaves the environment unchanged. No schedule or primitive selection is programmed into forward inference.

The output supports categorical cross entropy, full-support distribution supervision, or actor-critic training outside the model. An all-invalid mask raises an error; the environment must offer abstention or another public action. Exact handles, solver records, and resource budgets remain in simulator-protected storage, never purportedly protected by neural hidden coordinates.

Population helpers create six initial members, declarative equal-update allocations, and explicit parent/lineage/mutation records. Offspring inherit compatible model weights; optimizer reset versus inheritance is mandatory and recorded. Learning-rate and entropy mutations multiply by 0.8 or 1.2 with declared bounds. CPU checkpoint tensors are independent copies. Restoring sets the mutated learning rate after optimizer state loading. The runner must persist complete selection scores, episode exposure, timing, and replacement history; these utilities alone are **not an evolutionary experiment**. Equal optimizer steps are not equal FLOPs, and descendants are not independent seeds.

Mechanical tests use width16 solely for tensor/gradient/serialization fixtures. Main experiment callers must use width1024. No training or GPU job is launched by this module.
