# Exact identity attention oracle

`traversal_oracle.exact_attention_traverse` is a nonlearned mechanism control. It reads only the same runtime inputs as the learned models: raw identity keys, shuffled memory keys/payloads, supplied adjacency, start key and relation instructions. It does not read `token_nodes`, `start_nodes`, `path_nodes`, `targets`, or the clean graph. Even node ID metadata is unnecessary.

At every step, equality of the current retrieved raw identity with runtime entity keys yields exact one-hot query grounding. Memory keys produce exact one-hot key grounding, with unrelated distractor keys assigned to null. The oracle computes `Pq A_r Pk.T`, passes its nonzero mask to the existing `structural_attention`, and retrieves concatenated raw identity and one-hot categorical payload from token memory. The retrieved identity is rebound before the next instruction. Content logits are zero. This proves the actual grounding → bias → attention → retrieved identity → regrounding chain, independently of the direct graph-indexing oracle. The control requires one memory token per entity and functional binary relations; invalid/missing identities fail explicitly.

The procedure is privileged in its exact identity matching and raw-value transport. Its accuracy is not evidence of learned traversal or arbitrary latent binding. It provides the ceiling and a check that the neural mechanism's contractions/routing can realize the task at all depths. Corrupted graphs route according to their supplied edges; clean target metadata cannot correct them.

Nine tests cover depths 0, 1, 4, 8, 16, 32 with 64 nodes, randomized order and 19 distractors; exact full-path matches; distractor null binding; poisoned diagnostic labels; corrupted supplied graphs; and rejection of absent memory/branching relations. All oracle tests passed. Parent/runner informed; final integrated suite must resolve both before completion.
