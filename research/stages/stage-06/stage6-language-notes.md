# Stage 6 independent TCN semantic track

This track trains the shared four-phase ThinkingModel from public rendered text and shuffled visible answer choices. The forward API accepts only ActorInput(text, options); teacher semantic graphs, renderer/family names, generator seed, answer index and node count never enter it. Public lexical chunks use deterministic 64-bit SHA256 features and positions, not a parser. There is no execution engine or claimed joint runtime-language result.

The fixed 128-position graph decoder cross-attends to the current workspace. Positions are output positions in canonical compiler traversal, not labeled workspace rows. It predicts node presence, kinds, lexical value hashes and typed edges. Graph metrics require canonical alignment; they do not establish graph-isomorphism invariance. Edge slot ordering is implicit in canonical traversal positions. Lexical fidelity measures whole 64-bit hashes, not generated strings. Public hash collisions are audited.

The four arms are single-pass, recurrent, graph-supervised recurrent, and graph-supervised recurrent with paired surfaces. Same seeds initialize equal parameter sets; recurrent cells share parameters across steps. Paired English/Spanish views are generated from one construction and add task, pooled-state, choice and node-presence consistency losses. Spanish is held out only for the first three arms; symbols are held out for every arm. Extra Spanish exposure and task supervision confound attribution to consistency alone, so arm differences must not be described as an isolated consistency effect.

Semantic digests deduplicate and separate training/evaluation constructions. Additional English unseen-lexical evaluation alpha-renames answer entities consistently before compile/render on the evaluation constructions. It tests controlled entity renaming, not a new natural language or heldout compositions/motifs. Compiler/source/vendor and data hashes, distinct renderings, dedup counts, node bounds, task counts, curves at step zero and later, component losses, random-choice and oracle majority-position baselines and representative failures are recorded.

Pilot configuration: three seeds, four arms, eight updates, eighteen training constructions and nine evaluation constructions. This is a smoke/pipeline check, not evidence of learned generalization. Main budget is intentionally not frozen before pilot review. No training was launched during implementation.

Verification: Python compilation; focused remote torch tests on gb10-direct using ~/topoformer-pilot/.venv. Canary replaces all privileged data while preserving public data and checks identical forward tensors; option permutations preserve graph outputs and permute choice logits; graph losses/gradients are finite; decoder capacity is fixed and overflow rejected; semantic splits are disjoint; three actual rendered texts differ; renamed answer identity remains aligned.

Post-pilot metric hardening (does not change the frozen pilot): undefined graph precision/recall denominators now yield JSON null. Macro averages omit undefined examples and report defined-example counts, while graph counts report summed true positives, predictions and gold supports. The majority-position baseline remains explicitly an empirical evaluation oracle, not a training-estimated majority policy. Initial model state hashes, loss data hashes, final state hashes and serialized checkpoint hashes are recorded in manifest.json. Initial hashes must match across arms for each paired seed. Controlled renamed labels reuse novelentity0, novelentity1, etc. across heldout constructions; these labels are absent from training, but this is a bounded vocabulary reused across construction scopes, not an unbounded novel-lexicon claim.
