# Stage 5 task and execution boundary

The learning benchmark supplies an execution-ordered list of already segmented surface clauses. Each clause contains operation words and a noisy random lexical-feature reference. This isolates learning semantic lowering around an exact substrate; it does **not** learn segmentation, parsing, scheduling, arbitrary prose understanding or user-defined call planning.

The seven learned operation labels are `resolve`, `field`, `index`, `add`, `sub`, `rsub`, `mul`. Arithmetic calls the actual runtime builtin with `(current register, selected scalar)`; `rsub` reverses that argument order. Thus builtin recognition and operand binding are learned, while arbitrary function-definition identity binding and argument construction are not tested here. The independent exact language implements the broader grammar.

All initial runtime nodes are supplied as shuffled candidate rows. The public tensors include node type, scalar payload, index-slot payload, current/root scope flags, and every initial `binds`, `value_of`, `field`, `index`, `parent_scope`, `binding` edge. No call instances, computed return values, or evaluated answers are in that world. Arguments that are literal operands are initial observable values, not future computed results. Candidate IDs are never model features.

Reference keys depend on semantic `(kind, lexical label/literal/index)` equivalence, not on a gold path's unique entity ID. Two shadow bindings named `x`, or multiple slots at index `2`, share a key. `selector_mask` labels every semantically equivalent selector; the binding loss marginalizes their probability. Public `candidate_groups` records the same equivalence from observable descriptions for confidence aggregation. A selected name is resolved in the actual lexical scope by the interpreter. Therefore lexical-selector accuracy must not be described as learned scope resolution. Repeated literal or index selectors are likewise equivalent even when they belong to distinct runtime nodes.

Families cover nested alternating record/array lookup, lexical shadowing followed by builtin computations, sequential builtin composition, noncommutative argument ordering, immutable aliases sharing an object, and lookup combined with learned output interpretation. `depth` counts operations after initial name resolution. `nodes` counts additional visible distractor bindings, **not total graph nodes**. At fixed depth the graph has more nodes than this parameter; depth itself also increases graph size. These sizes must be labeled distractor-object counts in reports.

The output style is independently randomized per example. Numeric reporting predicts result + 64 among 129 classes; comparison predicts `result > comparison`; sign reporting has three classes. Runtime arithmetic remains exact and unrestricted; only generated arguments keep this benchmark's results inside [-64,64]. Initial scalar values include negative, zero and positive values. Report majority-class frequencies because task families/styles need not be perfectly balanced.

`run_actions` accepts predicted operations and selectors, deep-copies the initial runtime and changes a protected entity register only after a typed primitive succeeds. It never reads gold actions/results/registers. Incorrect choices persist. Rejection or confidence deferral stops the trajectory and is not task success. `evaluate_execution` consults gold only afterward; scalar steps compare scalar semantics and object steps compare entity identities. The complete-trajectory metric is therefore complete **semantic state** correctness, not an identity claim about newly allocated equal-valued scalar nodes.

The `ambiguous` stress condition removes the initial reference cue, labels lowering as null, and marks the task unanswerable (`expected_valid=False`, no gold runtime result). This is a missing-cue/unbound test, not ambiguous natural-language resolution. The `invalid` stress condition supplies field access with a binding selector before an object register exists. It has no answer and tests schema rejection. Numeric/output labels in both cases are placeholders and must be excluded from answer accuracy. Corruption rewires initial scalar-value edges, changing both the public tensor graph and exact interpreter world while preserving clean targets.

The protected adapter reports invocation, deferral, rejection, semantic binding and primitive correctness, complete semantic trajectory, recovery after a wrong state, and symbolic wall time. Timing includes runtime copy/execution but excludes gold evaluation in the stored per-execution time. Runner total adapter timing additionally includes metric evaluation and must be labeled accordingly.

Generator result labels are independently calculated: lookup families retain the sampled leaf scalar before constructing enclosing objects, and arithmetic families calculate the scalar expression directly in the generator from sampled operands. Exact runtime execution must agree with that independent result before the task is accepted. Runtime-generated register traces remain diagnostics only. Deep 16/32-step tests cover every family; a fault-injection test ensures changing the executor's scalar result triggers the independent check rather than silently becoming the target.

`decode_surface` renders the actual public token sequence plus its separately supplied reference description for failure inspection. `render_output` converts the learned report class to a fixed phrase such as “the value is 13”, “yes”, or “negative”. This is a controlled learned classification/lifting task followed by a fixed vocabulary decoder; it is not learned free-form language generation.

Each nested/alias/mixed world additionally contains one matched decoy object chain: identical depth, field names, index labels, and shape, but independent scalar payloads and a distinct root binding. The target and decoy terminal values are sampled to differ. Changing only the first name selector therefore changes the result while every subsequent operation and lexical reference remains identical. The generator independently checks both results. This removes the unique-terminal-field shortcut; the final field's lexical key has multiple matching slots and cannot uniquely identify an answer without object context. One decoy is used rather than copying a chain per distractor to bound dense graph cost.
