## Scientific integration checks

- **Within-condition pairing is exact.** `study.py:189–201,314–321,411–412` constructs a fresh common model using the same seed and copies every matching shared tensor, including the optional identity table. Every variant reconstructs the same graph/window schedule from the same local generator (`204–209,319`). Each step uses the graph index to select both its examples and its supplied topology (`338–340`). Extra graph-input and coefficient parameters are explicit. Node-identity controls have identical parameter counts and full initial state across none/soft4/hard; transfer never creates the table.
- **Count nesting is real and does not leak larger-budget statistics.** The common fixed-process pool is generated once at the maximum required count (`135–148`) and training uses prefixes (`167–177,408`). Normalization is fit to the smallest training prefix (`161–164`), with distinct trajectory RNG seeds for validation and test. Across-count schedules have different sampled index ranges; the design and methods accurately limit exact schedule matching to within a count/case. Reused seeds alone would not guarantee independently regenerated trajectory prefixes, but the implementation uses a shared pool and slices it, which does.
- **Transfer has one shared model and disjoint graph identities.** `study.py:150–160` creates graph-indexed datasets and checks graph-hash intersections across splits; `314–348` trains one model over uniformly sampled graph indices. Fixed and mixed training cases evaluate the same test graph/trajectory seeds. Models contain no node-count-specific parameter in these cases. Sparse graph probability is `min(degree/(n-1),1)` (`study_data.py:23–25`), so expected nonself indegree remains fixed as size grows. The full preset uses sparse transfer only (`study.py:283`); fixed robot experiments must not be advertised as morphology transfer.
- **Supplied topology cannot change the data-generating process.** `_graph` returns corrupted supplied tensors (`study.py:181–186`); labels and trajectories remain attached to the original `Dynamics`. Fixed-process validation/test preserve the original graph seed, so the seeded corruption is identical across those splits and variants. The corruption implementation clones input, preserves self support, counts original directed nonself edges, draws additions from original nonedges, and records realized precision/recall (`study_data.py:50–106`). Clean-trained runtime corruption is a separate evaluation label and occurs after training (`study.py:421–430`).
- **Generating dynamics and graph directions agree throughout.** `data.py:90–93` computes target row `i` from source column `j` via `state @ weights.T`; attention uses row query/column key and graph-input uses `adjacency @ histories`. Signed absolute row mass is bounded below 0.8, giving the stated transition Lipschitz upper bound 0.9. This is a sufficient contraction condition, not a claim that graphs are identifiable from the sampled histories.
- **Information asymmetry is explicit.** Typed models receive actual process coefficients and form positive/negative magnitude channels (`study_model.py:76–87`), not just adjacency. This information is labeled in rows (`study.py:436`). The full preset uses typed only on clean signed fixed processes. Graph-input is a normalized neighbor-history aggregation before unbiased attention (`study_model.py:72–75`); it is correctly described as input message passing. Added-edge behavior for typed models remains outside the study's declared comparison.
- **Deterministic rollout is indexed correctly.** The observed prefix is `series[:, :history]`; the stochastic target begins at `series[:, history]` (`study.py:251–255`). `deterministic_future` starts from the last observed state and applies the noise-free transition once for the first prediction. Model recursion shifts normalized history one step, appends its own prediction, and is unnormalized only for metric comparison (`232–241,254–265`). Neither target future nor deterministic future is fed into the model. Oracle deterministic error is zero by construction and its stochastic error is correctly only a diagnostic.
- **One-step baselines and thresholds are training/validation grounded.** Oracle predictions unnormalize the last observed state before the transition. The normalized zero predictor is implemented algebraically as target plus `mean/std` (`study.py:219–226`). Thresholds use validation oracle and zero errors, invalidate nonpositive gaps, and preserve nonattainment as null (`351–361`). Test evaluation occurs only after all optimizer updates and validation checkpoints.
- **Operational provenance is adequate for this run.** Initial/shared/final/checkpoint model hashes, schedule hash, split seeds, graph/weight hashes, normalization, counts, timing, and process RSS are retained. The row is complete only if both the optimizer budget and all scheduled test evaluations finish (`431–434`). Dense attention and the cooperative deadline are accurately disclosed. Hashes are audit fingerprints, not saved reloadable model checkpoints.
