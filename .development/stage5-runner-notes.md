# Stage 5 training and measurement protocol

`runtime_study.py` is isolated from all earlier runners. The main configuration fixes three paired seeds, 400 updates, a 200-update supervised warm phase, batch 16, and 64 evaluation examples per cell. Twelve cells cross 4/8/16/32 post-resolution operations with 8/32/64 distractor bindings. These are **not total runtime node counts**; raw records include actual candidate-node and clause counts. Six families are pooled with a fixed deterministic mix; each cell also contains family counts. Fresh 48-bit names, fresh lexical reference features and shuffled world nodes occur in every generated batch.

Ten variants share parameter shapes, initialization seed, data schedule and public initial world. Exact oracle lowering is privileged. Cold supervised lowering minimizes operation cross entropy plus negative log probability mass on all semantically equivalent selectors. Primary neural controls receive those same auxiliary labels, plus a favorable additional numeric-result target. They consume the full public graph as edge tokens; graph-data and soft variants additionally have architectural structure paths. Their numeric-result head is evaluated as a prediction, never labeled actual interpreter execution.

Cold answer-only and post-warm beta-zero lowering use sampled categorical actions and REINFORCE. Reward is correctness of the final learned lifted output, vetoed on invalid execution; no intermediate binding reward is supplied. The lagged scalar exponential baseline is initialized at zero and updated after the loss. The log probability is the sum across all sampled operation and selector decisions, without dividing by depth. Post-warm beta=.1 retains weaker direct supervision. Warm-frozen freezes every parameter except the lifting head and style embedding; it is a maintenance control, not answer-supervised binding acquisition.

Exact execution uses predicted actions on persistent state. Result-to-output lifting is trained on the actual result, with zero as a numeric placeholder when execution fails; failed executions cannot count as successful answers. Gold-result lifting is an explicitly privileged diagnostic for runtime variants. Neural controls' unused lifting head is not scored. Separate conditional metrics distinguish correct binding, correct whole lowering (binding plus operation), exact result and output accuracy. For neural controls, an auxiliary-lowering execution audit is labeled separately from their own prediction trajectory.

Confidence thresholds are predeclared `[0, .05, .1, .2, .4, .6, .8, .95]`; no OOD threshold is selected. Actual successful primitive invocations and wrong invocations count only reachable steps before stopping. Hypothetical confidence gates over all clauses are separate. Rejection/deferral does not count as a correct answer. Ambiguous reference erasure and invalid-type conditions have undefined task answers: `defined_examples=0`, task accuracy null, and rejection/deferral counts reported separately. No null examples are included in training, so this is an extrapolation diagnostic.

Wrong-graph evaluation corrupts observable adjacency and the executor's world consistently while preserving clean labels. Permutation rotates selected candidate indices at the execution boundary; it is an interface intervention, not retraining. Held-out surface templates reorder trained lexical pieces; canonical and synonym templates alternate during training. Names are fresh in all splits, so the renamed condition is another fresh-name sample, not an unseen-character-vocabulary test.

Raw JSONL records contain source/config hashes, per-parameter initialization hashes, training schedule hash, step-zero and intermediate curves, final matrices, raw metric counts, bounded failure traces, family counts and timing. Symbolic time sums actual predicted executions and excludes gold diagnostic re-execution. Neural training time includes tensor computation and adapter/diagnostic overhead; it is an operational timing, not a hardware-kernel profiler. Checkpoint files stay remote; compressed metrics/configs/reports are committed.

## Pilot checks

A remote isolated overlay passed all ten variants at two updates and nine runner tests. A 25-update budget pilot took 2.88 seconds for supervised exact execution and 2.04 seconds for graph-data, including four small evaluation cells. It sets the 400-update CPU budget; it is not scientific evidence. A shallow-only oracle lifting pilot is run before main source/config freeze to inspect the output-boundary optimization independently of lowering.

The shallow oracle lifting pilot at 400 updates reached 0.375 validation output accuracy while exact runtime result/trajectory accuracy remained 1.0. This identifies lifting optimization as a bottleneck before any main experiment. Root coordinates a pre-main lifting design decision; this pilot must not be treated as the final architecture's outcome. Template variants alternate in blocks of the training-depth cycle so that template choice is not deterministically coupled to depth.

The paired RBF lifting pilot uses the same config, initialization seed and training data schedule as the scalar-only pilot; only `runtime_model.py` changes. It reaches 0.6875 validation and 0.703125 independent shallow output accuracy. Exact execution remains perfect. Both source snapshots and compressed raw metrics are archived under `results/stage5/pilots`; the main architecture is frozen with this disclosed bounded-numeric feature prior and no further pilot tuning. Final records split output/lifting counts by numeric report, comparison and sign style. Training timing is named `neural_and_diagnostic_train_seconds` because it includes diagnostic adapter work; it is not a pure neural-kernel measurement. Confidence intervention rates compare actual post-permutation trace selectors, not the original model choices.

## Selector-read supplement (declared after main launch)

Partial first-seed main results were already visible when this follow-up was specified. It is not retroactively preregistered as part of the main sweep. The concern is that the graph-data and protected-learned controls train auxiliary lowering but their neural recurrent controller does not directly consume that semantic distribution. This repeats the retrieval-prior confound identified in Stage 3.

`configs/stage5-selector.json` contains three additional controls: learned-selector graph-data, learned-selector protected recurrent state, and oracle-semantic-selector protected recurrent state. All use the unchanged 400-update, three-seed, paired data schedule and beta=1 auxiliary loss. The optional read passes the soft selector-weighted node memory into the recurrent controller and operation-probability-weighted operation embeddings into its instruction. It adds no learned parameters or random draws. It performs no exact transition.

The oracle selector is privileged only at the semantic interface: operation probabilities are one-hot and selector probabilities are uniform across the complete semantic equivalence class, including repeated lexical names or slots. It does not select a unique correct shadowed runtime node. Learned logits still receive auxiliary training; reported effective binding/operation metrics for this oracle control describe the supplied semantic interface. Neural numeric results remain predictions, and exact-execution/trajectory metrics remain unavailable; auxiliary-lowering execution is explicitly a counterfactual audit.

The original ten default variants are frozen in `MAIN_VARIANTS`. Root verifies common initialization/data/schedule hashes and unchanged default outputs before reusing main controls as comparisons. The supplement is launched only after the main sweep completes.
