# Controlled expression data

`thinking_tasks.py` is a separate controlled benchmark, not a TCN language lesson. `generate_episode` returns immutable `Episode(public, gold)` records; the actor receives only `public`. Initial typed literals, named result capacity, whole-program clause segmentation, and three externally arriving evidence frames are declared supplied priors. No rewrite ordering is provided by the default `scheduling='learned'`; a runner using trace order must explicitly report supplied scheduling or training-only teacher forcing.

Two independent arithmetic lanes each contain depth 1–32 operations; ±1 operands bound every integer to [-38,38]. add/sub/mul and randomized ordered arguments prevent treating subtraction as commutative. Arithmetic values are generated directly and independently audited by replay, and a separate protected-runtime replay test checks the interface. Initial distractors are unused visible literals; an unbound clause supplies a genuine null case. Operation/result identities and capacity order are randomized.

Every evidence frame contains the entire program. Primitive alternatives and ordered operand alternatives are progressively resolved. Lane 0 resolves earlier than lane 1. Explicit per-clause uniform hypothesis sets produce candidate-local masses 1/4, 1/2 and 1; actual unavailable arguments make readiness zero. The generator uses symmetric ±1 true/alternative operand values, avoiding a decoy value-range shortcut. These are finite local semantic ambiguity distributions, not interpolated time-based confidence labels. Full-program global correlations and future context are not part of this local posterior. `readiness_targets` is privileged training/scoring code and accepts the actual available register IDs; it cannot be an actor proposal mask. `context_visible=True` adds the final comparison target once its cue has been released. Formal type validity is still determined by the runtime, independently of this posterior.

Context is separate from the evidence frames and is released only once both public root return IDs are actually present. It specifies an ordered comparison of the two returned lane values. The final answer is the comparison boolean; the numeric result target is lane 0's arithmetic result. `paired_contexts` creates same-numeric-result/different-answer diagnostic pairs by reversing comparison order, conditioning those diagnostic pairs on unequal roots. Ordinary generation does not reject outcomes. The compare thus requires previously returned values plus an independent ordering cue. These supplied literal and clause priors do not establish general language induction.

Canonical, infix, prefix, reversed-clause/labelled-argument, and lexical renderers consume only observable statements and alternatives. They preserve one hidden DAG while yielding distinct surfaces. Exact DAGs use the shared `SemanticGraph` node/edge schema, explicit ordered arguments and return edges. `episode_hashes` records generator version, source, public, privileged and semantic hashes. Trace/readiness/hypotheses/results/answers remain only in `GoldEpisode`.

Validation: seven stdlib tests cover depth32 reproducibility and bounded arithmetic, independent exact audit, runtime replay, context pairs, public-field separation, all finite readiness values/null, five distinct matched renderers, and malformed options. No Torch or training was run locally.
