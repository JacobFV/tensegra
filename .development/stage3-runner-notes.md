# Stage 3 runner

`grounding_study.py` trains with answer cross entropy only, fresh seeded graphs/keys/values/order/distractors each optimizer step, and cyclic depths 1–4. The model input boundary explicitly strips all gold and clean-graph diagnostic fields. Training, validation, and final evaluation seed namespaces are separate. All variants share exact data schedules; initial per-parameter hashes expose which architectural ablations do not have identical initialization.

The evaluation grid varies one factor at a time, plus one declared depth-32/64-node joint test. All conditions share an evaluation seed namespace so corrupted and clean conditions preserve the same underlying task. Graph corruption changes the supplied structure, not the clean target. Graphs can revisit nodes: mean distinct nodes in the true path is recorded.

Metric definitions: `grounding_accuracy` uses pre-update query grounding against path[t]. `exact_pre_step_grounding` requires those predictions all correct. `exact_path_completion` additionally requires every post-update grounding to match path[t+1], including the destination. The frozen mode post-update probe is freshly computed solely for diagnostics; routing remains frozen. `exact_attention_path_completion` requires attention argmax token to match every next node. These diagnostics are distinct from task accuracy. `pre_step_next_node_mass` is pre-update probability on the next node, while `structural_next_node_mass` pushes query grounding through the supplied graph first. `clean_next_attention_mass` measures clean next-node attention. `relation_attention_mass` measures attention on the supplied successor of the clean current node, so it differs under corruption. Null metrics include the null channel. Direct algorithm and one-hot attention oracle task/path metrics are separate.

Runtime is CPU with <=2 threads. RSS is process cumulative high-water (not isolated per-model allocation); training time excludes diagnostics, evaluation time includes them and both oracles. Config and exact source file hashes gate resume. Failures abort rather than producing partial successful rows. Raw metrics contain per-step means and one full query-grounding distribution trace per condition/run. Each completed run is flushed to JSONL.

The identity-initialized soft condition includes an explicit keyed-binding architectural prior. `random_init` removes it. Graph-input receives the graph through message passing with known cosine identity matching; it is a strong alignment-prior baseline. Projection period 4 cycles trained projection slots at deeper test depths, rather than invoking untrained new-layer parameters.

Runner validation additions check that correct initial grounding with deliberately wrong final grounding/attention cannot pass full-path metrics, verify input gold exclusion, oracle agreement, one-factor grid uniqueness, resumption configuration matching, and exact ordinary-parameter initialization pairing for periodic projections. Plain inference overhead uses three warmups and ten repeats with diagnostics disabled; do not interpret cumulative RSS as a separately isolated model measurement. `stage3-pilot.json` uses 100 training steps and IID-only evaluations for feasibility; the prespecified full grid remains 400 steps per run.

## Supplemental matched identity-content prior

The primary setup initializes soft grounding to recognize identity keys, while ordinary content Q/K starts randomly. This can disadvantage graph-as-data when it first must learn to retrieve the current entity before using its graph-message value. The separate `stage3-keyed.json` experiment therefore gives all three modes the same fixed cosine-content logit prior β=8 on current raw query identity versus immutable token identity. `soft_keyed` additionally uses structural strength initialized to 16, roughly compensating current-node attraction to permit next-node routing; `graph_input_keyed` and `none_keyed` carry identically initialized strengths although their routing modes do not use them. This is a declared supplemental architecture/control comparison, not an OOD-selected replacement of the primary grid. All three share exact initial parameters, 400 steps, three seeds, temperature .05, data generation and final evaluation conditions. Original configs and artifacts remain unchanged.
